# 구조와 확장 지점

## 구성 경계

| 계층 | 위치 | 역할 |
|---|---|---|
| 공통 실행·UI | `extension/` | 아이콘, 설정, 진행 상태, DOM/SAP 어댑터, 기록기 |
| 생성 템플릿 | `templates/script/` | 개인 매크로의 최소 등록 구조 |
| 개인 작업 | `local/` | 실제 입력값, 결재자, 개인 매크로, 캡처 |

`tools/build.mjs`가 실행 목록과 manifest를 만든다. 새 설치의 목록과 사이트 권한은 비어 있다. 특정 기관의 업무 매크로는 기본 제공하지 않는다. 개인 빌드에만 `local/scripts/`의 활성 스크립트와 해당 사이트 범위를 포함한다. 개인 스크립트 폴더를 연결하면 `scripts/runtime.js`가 그 폴더의 변경을 별도로 등록한다. 개인 스크립트만 변경하면 확장 새로고침이 필요 없다. 공통 확장·manifest 변경도 빌드 완료를 감지해 자동 적용한다.

공통 네임스페이스는 `window.MacroStudio`이다. `features`는 사이트 기능, `launcher`는 스크립트 등록 UI, `dom`·`sap`는 입력 어댑터다. content script의 world마다 별도 네임스페이스가 있다.

## 실행 world

일반 개인 매크로는 ISOLATED world를 사용한다. SAP 기본 API를 사용하는 개인 매크로는 MAIN world를 사용한다. MAIN world는 사이트와 JavaScript 환경을 공유하므로 비밀 정보나 확장 권한을 두지 않는다.

도구모음은 `action.default_popup`의 `ui/popup.html`을 열며 `openPanelOnActionClick`은 꺼져 있다. 팝업은 현재 사이트 ON/OFF와 폴더 관리 진입만 제공한다. 권한이 필요한 기록·내보내기는 확장 사이드패널과 서비스 워커가 처리한다. 사이트 안의 ‘새 자동화 만들기’ 버튼은 ISOLATED listener가 실제 사용자 클릭을 확인한 뒤 사이드패널을 연다. 사이트의 `postMessage`로 임의의 코드 실행이나 AI 인증을 요청하는 기능은 없다.

## 스크립트 보관함

확장 내부 화면은 모두 `ui/panel.html`을 공통 사이드패널 컨테이너로 사용한다. 페이지 버튼의 만들기·보관함, 도구모음의 설정·업데이트, 내부 링크는 새 탭이나 별도 창을 만들지 않는다. 페이지별 프레임을 처음 열 때만 만들고 숨겼다 다시 표시하므로 화면을 바꿔도 기록·설명·검색·입력 상태를 유지한다. 내부 탐색 메시지는 확장 origin과 실제 자식 프레임, 허용한 화면 이름을 검증한다. 업데이트 후에도 예전 확장 HTML 탭을 다시 생성하지 않는다.

빌드는 `core/script-catalog.json`에 스크립트 id·이름·사이트 범위를 생성한다. 공유용 카탈로그와 개인 스크립트가 없는 새 개인용 카탈로그는 빈 배열이다. 개인용 카탈로그만 개인 스크립트를 포함한다. `script.json`의 id와 `launcher.register()`의 id는 같고 다른 스크립트와 겹치지 않아야 한다.

보관·삭제 id는 서비스 워커가 `chrome.storage.local`의 `macroStudioScriptLibrary`에 직렬 저장한다. 페이지에서는 ISOLATED listener가 런처 안의 실제 사용자 클릭만 보관 요청으로 전달한다. 워커는 sender·카탈로그·사이트 범위를 확인한다. 복원·삭제는 확장 전용 `ui/library.html`에서만 허용한다.

MAIN world에는 DOM 이벤트로 표시 상태만 전달한다. 이 이벤트는 저장 권한을 주지 않는다. 런처는 저장 상태가 준비되기 전과 보관·삭제된 항목의 실행을 막는다. 저장 변경을 받으면 열려 있는 탭도 다시 읽는다. 실행 중인 작업은 계속 진행되며, 이후 실행 목록에 상태를 반영한다. 목록 삭제는 소스 파일 삭제나 manifest의 코드 제거를 뜻하지 않는다.

사이트별 선택은 `macroStudioSites`에 http(s) origin과 boolean만 저장한다. 팝업에서 ON을 누를 때 필요한 해당 사이트 권한만 요청하고, 워커는 실제 탭 origin을 다시 확인한 뒤 런처를 연결한다. 저장 이벤트는 같은 사이트의 열린 탭에도 반영된다. 명시적 ON은 스크립트가 없어도 파란 버튼을 표시하며, 명시적 OFF는 호스트·메뉴를 숨기고 새 실행·기록을 막는다. 저장된 값이 정확히 true인 사이트만 켜진다. 설정이 없으면 기본 OFF이며, 공개 예제·가져온 스크립트·호스트 권한의 존재로 ON을 추론하지 않는다. 초기화로 사이트 설정이 지워지면 팝업·런처·새 실행·기록 모두 OFF로 돌아간다. OFF는 권한과 등록 코드를 제거하지 않으며 진행 중인 매크로는 완료까지 표시한다. 기록은 보존하고 종료한다.

## 연결된 스크립트 폴더

작업실 안에서 폴더 선택·읽기 권한 복구·절대경로 확인·실행 허용·사이트 권한을 순서대로 설정한다. `core/script-setup.js`가 경로와 준비 상태를 판단하며, 준비 완료 전에는 기록·생성을 잠근다. 절대경로는 폴더 핸들과 함께 확장 전용 IndexedDB에만 보관하고, 사용자가 복사하는 프롬프트에 명시한다. 폴더 연결은 공통 `ui/scripts.js`에서 관리한다. 상단 메뉴는 만들기·내 매크로 두 개이며, 패널은 만들기·내 매크로 진입마다 `setupReady`로 공통 준비를 확인한다. 부족하면 메뉴에 없는 사용 준비 프레임(`scripts.html`)을 표시하고 완료 후 요청 화면으로 복귀한다. 경로 수정은 같은 프레임을 관리 모드로 열며 저장 또는 계속하기로 복귀한다. 업데이트는 만들기 프레임을 재사용한다. 완료한 설정은 저장 경로 한 줄과 접힌 ‘폴더 설정·사이트 설정’으로 줄인다. 파일 확인과 매크로 관리는 내 매크로 화면에서 한다. 만들기 화면의 중복 파일 목록과 입력 항목 추가 조건 칸은 제거하고 작업 설명 하나만 사용한다. 이전 추가 조건 초안은 작업 설명으로 한 번 옮겨 보존한다. 같은 상태의 목록·체크 항목은 DOM을 유지한다. 설정 화면은 반복 타이머 없이 저장·권한 변경과 화면 복귀로 갱신한다.

`scripts/directory.js`는 사용자가 선택한 폴더 바로 아래, 또는 정해진 `local/scripts`·`scripts` 위치의 `script.json`과 명시한 `.js`만 읽는다. 빈 폴더도 연결하며 매 동기화에서 알려진 하위 위치를 다시 확인한다. 폴더 핸들과 원본·컴파일된 코드의 정상 스냅샷은 확장 IndexedDB에 저장한다. 공개 저장소와 페이지의 저장소에는 쓰지 않는다. `chrome.storage.local`에는 목록 갱신용 revision·개수·오류 상태만 전달한다.

Chrome `userScripts`에 코드를 등록·갱신하고, 허용된 현재 페이지에도 주입한다. 공통 런처를 사용자 코드에 일시적으로 대신 제공해 UI 정의와 `run`을 수집한다. 코드 자체는 해당 MAIN 또는 USER_SCRIPT world에 유지하고 UI의 데이터만 공통 런처에 전달한다. 이미 로드된 공통 MAIN 기능은 프로토타입을 통해 재사용할 수 있다. 사이트별 업무 기능은 개인 매크로가 명시적으로 구현한다. 개인 feature 설정은 별도 객체에 둔다.

런처의 실제 submit 이벤트를 ISOLATED listener가 shadow root 안에서 확인하고 id·revision·현재 입력값을 검증한 뒤에만 실행 요청을 보낸다. 워커도 tab·frame·사이트 범위·현재 revision·보관·삭제 상태를 검사한다. 진행 결과를 돌려주는 DOM 이벤트는 표시 용도다. 사용자 스크립트에 확장 API 메시징을 열지 않는다.

현재 페이지의 런처는 같은 id를 교체하며 실행 중 교체는 완료 뒤로 미룬다. 카탈로그의 available id로 사라진 항목을 숨겨 기본 빌드에 남은 옛 항목이 되살아나지 않게 한다. 폴더가 연결되기 전에는 빌드에 포함된 기존 개인 스크립트를 그대로 사용할 수 있다. 연결 후에는 가져온 스냅샷이 개인 스크립트 목록의 기준이다. [동기화 사용법](script-sync.md)

## 기록

`ui/reset.html`에서 명시적으로 확인한 초기화만 워커가 받는다. 사이트 content script에는 초기화 권한이 없다. 개인 실행 중에는 거부하며, 진행 중인 동기화·연결을 마친 뒤 사용자 코드 등록과 IndexedDB 원본을 지운다. 초기화 화면의 스크립트 개수는 보관 중이거나 빌드에 포함된 항목까지 계산한다. 초기화할 때 기본 카탈로그의 모든 id를 삭제 상태로 남겨, 빌드에 남은 예전 사본도 실행 목록이나 보관함에 되살아나지 않게 한다. 원본 파일과 빌드 파일 자체를 지우지는 않는다. 새 동기화와 실행은 그동안 진입하지 못한다. IndexedDB의 개인 정보 없는 reset epoch는 초기화 전에 열었던 폴더 선택기가 뒤늦게 핸들을 다시 저장하는 일을 막는다.

기록은 탭 하나를 대상으로 하며, 사용자가 허용한 도메인의 프레임만 관찰한다. 서비스 워커가 sender의 탭·origin과 recording id를 검증하고, 이벤트를 정리해 `chrome.storage.session`에 직렬 저장한다. 워커가 중단되어도 같은 브라우저 세션에서 읽을 수 있다.

기본 정보는 action, URL의 origin/path, frame id, 대상의 라벨·선택자 후보·SAP 필드, 입력값이다. 버튼 태그에 한정하지 않고 실제 클릭·더블클릭·오른쪽 클릭·중간 버튼 클릭을 수집하며, 같은 대상의 연속 두 클릭과 dblclick은 한 더블클릭 단계로 합친다. 열린 Shadow DOM은 composedPath와 호스트별 선택 경로로 기록한다. 쿠키나 네트워크 응답, 화면 영상은 수집하지 않는다. 기록은 agentPrompt 생성에 쓰는 증거이며 바로 실행하는 코드가 아니다.

네이티브 입력은 신뢰된 input/change로 수집한다. ARIA 체크박스·라디오와 SAP 콤보박스, 직접 포커스하거나 조작한 입력란은 실제 포인터·키보드 조작 직전에 해당 필드만 관찰하고, 조작 후 바뀐 boolean/표시값을 change로 저장한다. 팝업의 선택 항목은 aria-controls로 입력 소유자를 확인한다. SAP가 DOM을 교체하면 같은 업무 필드가 정확히 하나일 때 다시 연결한다. 사용자 조작 직전 같은 폼·대화상자의 보이는 입력란도 최대 150개까지 관찰한다. 직접 입력과 주변 값 변화(`context-change`)를 구분하며 읽기 전용 계산값은 입력으로 추정하지 않는다. 관찰은 마지막 조작부터 최대 30초이며 종료·새 기록에서 해제한다. 달력 팝업 선택처럼 입력란의 value 프로퍼티만 바뀌는 경우도 사용자 클릭·키 입력 직후에 확인한다. 네이티브 이벤트가 함께 발생하면 중복 기록을 피한다. 합성 이벤트 자체는 계속 무시하고, 조작하지 않은 기본값이나 계산 결과를 새 입력으로 만들지 않는다. 입력란의 라벨·타입·선택자·SAP 필드·placeholder/pattern·읽기 전용 여부는 값 없이 `fieldContexts`에 따로 보관한다. 이 정보는 실제 조작 단계가 아니며, 기록 전체에서 600개·20개 페이지/프레임 문맥을 넘기지 않는다. 민감 필드는 입력과 식별 정보 양쪽에서 제외하고 sender의 탭·origin·recording id 검사를 동일하게 적용한다.

기록기가 추정한 단계 모드에는 `modeSource=automatic`을 붙인다. 확장 UI의 모드 편집 요청은 워커가 검증한 뒤 `user`로 저장한다. 출처가 없는 과거 기록은 내보낼 때 `legacy`로 표시하며 원본 기록은 바꾸지 않는다. 프롬프트는 자동 분류를 참고 자료로 설명하고 사용자가 명시한 목적·중단 지점을 우선한다. 중간 준비 화면은 사이트 문서와 기존 구현으로 확인하고, 사용자 지정 수동 단계와 실제 최종 제출은 실행하지 않는다.

### 내부 프레임 자동 감지

`recorder/frames.js`는 선택 권한 `webNavigation`이 있을 때 `getAllFrames()`로 실제 프레임 주소를 확인한다. `src` 문자열 추측을 사용하지 않는다. 같은 origin을 묶고 이미 허용된 사이트를 확인하며, UI에는 전체 URL 대신 origin과 프레임 id만 반환한다. `about:blank`, `data:`, `blob:` 같은 특수 문서는 현재 감지 목록에서 제외한다.

탭 활성화·URL 변경·권한 변경과 webNavigation의 내부 화면 로드 알림으로 현재 대상 탭을 확인한다. 화면 복귀와 수동 ‘내부 화면 다시 확인’도 지원하며 반복 스캔 타이머는 사용하지 않는다. 로드 알림에는 tabId만 전달하고 페이지 URL·입력값은 전달하지 않는다. 기록 중이면 다른 탭으로 이동해도 기록 탭을 대상으로 유지한다. 미허용 후보의 체크 상태를 유지하고, 실제 버튼 클릭 안에서만 `permissions.request()`를 호출한다. 기존 권한이면 요청을 건너뛴다. 승인 후에는 현재 페이지 주소를 다시 검증하고 허용된 프레임 id에만 기록기를 연결한다. 일부 프레임이 사라져도 최상위 페이지 기록은 유지하고 연결 실패를 안내한다.

추가로 승인한 프레임은 기존 recording id와 단계 목록을 유지한 채 연결한다. 나중에 로드된 프레임도 같은 기록 탭에서 기존 사이트 권한이 확인되면 기록에 참여한다. 프레임 탐지·권한 요청·기록 연결 요청은 확장 전용 UI에서만 허용한다.

기록 중 새 내부 주소가 탐색을 확정한 `webNavigation.onCommitted` 시점부터 확인하며, `onCompleted`에서도 다시 확인한다. 미허용 주소가 발견되면 기록을 일시정지하고 열린 사이드패널 안에 허용 안내를 표시한다. 패널이 닫혀 있으면 작업 페이지 오른쪽에 일시정지 안내와 패널 열기 버튼을 표시한다. Chrome은 사용자 클릭 없이 닫힌 패널을 열 수 없으므로 별도 HTML 창으로 우회하지 않는다. 다른 탭의 프레임은 현재 기록을 방해하지 않는다. 주소만 표시하고 전체 URL·세션 값은 전달하지 않는다.

Chrome 권한 창은 허용 안내의 실제 버튼 클릭에서만 요청한다. 승인 뒤 현재 프레임과 권한을 다시 조회하고 기록기 연결이 모두 성공해야 같은 recording id로 재개한다. 거부하거나 안내 창을 닫아도 기존 단계는 보존되고 일시정지를 유지한다. 작업실에서 허용 안내를 다시 열거나 기록을 끝낼 수 있다. 연결 실패는 기록 재개로 처리하지 않고 오류로 남긴다. 승인 전 동작을 소급해서 복원하지 않으며 기록 내보내기에도 일시정지가 있었음을 표시한다.

## 빌드

- `build`: 공통 확장 + 활성화된 `local/scripts/*/script.json` → `dist/`
- `build:public`: 공통 확장만, 스크립트 목록은 빈 배열 → `dist-public/`
- `local/scripts/*/script.json`에 명시되지 않은 개인 설정이나 별도 파일은 자동 등록하지 않는다.
- 공유 빌드는 개인 디렉터리를 읽지 않는다.
- staging 폴더에서 파일을 확인한 뒤 output을 교체한다. 파일 내용의 SHA-256 식별자를 `core/build-info.json`에 쓰고, 검증이 끝난 staging만 output으로 교체한다. 같은 내용의 빌드는 식별자가 같다.

서비스 워커는 현재 로드한 빌드 식별자를 보존하고, 캐시 없이 읽은 완료 빌드와 비교한다. 화면 복귀·수동 확인과 30초 알람이 같은 직렬 경로를 사용한다. 자체 UI의 반복 타이머는 사용하지 않는다. 기록 중이거나 사용자 코드 실행 중이면 미루며, 적용 직전 새 실행을 잠그고 진행 중인 동기화·연결을 마친다. 런처의 실행 상태도 확인한다. 작성 중인 설명을 저장시킨 뒤 기록·설명을 IndexedDB에 임시 체크포인트로 보관한다. Chrome이 재로드 때 세션 저장소를 비우므로 새 워커는 요청 처리 전에 이를 복원하고 체크포인트를 제거한다. 같은 빌드의 중복 적용과 빌드 중간의 누락·잘못된 마커는 무시한다. 사이트의 폼을 잃지 않도록 웹페이지 자체를 새로고침하지 않는다.

새 작업은 실제 진입점과 로드 순서를 검증해서 `local/scripts/<id>/script.json`에 명시한다. 공통 SAP API와 프레임 경계는 [SAP 어댑터 안내](sap-adapter.md)를 참고한다.

## AI 연결 경계

현재는 기록·프롬프트를 사용자가 코딩 에이전트에 전달한다. 향후 provider별 companion을 추가할 수 있다. 확장에서 사용자 PC의 코딩 에이전트를 직접 실행할 수 있다고 가정하지 않는다. native host·명시적인 설치·권한 경계가 필요하다. [다음 단계](roadmap.md)

작업 기록 종료 시 별도의 기록 확인 토글을 펼치지 않는다. 단계 목록·삭제는 기존 ‘전달할 내용 보기’ 안에 두고, JSON 저장·기록 지우기는 기록 영역의 보조 동작으로 유지한다. 지시문 복사는 Clipboard API가 성공한 뒤에만 체크와 ‘복사됨’을 표시하며, 복사한 내용과 현재 지시문이 달라지면 초기화한다. 실패 시 성공 표시 없이 미리보기의 직접 복사 경로를 제공한다.

이름 수정은 확장 제어 페이지의 `local:rename` 요청만 받는다. 작업·동기화·연결을 비운 뒤 저장된 폴더 핸들의 읽기·쓰기 권한을 확인하고 선택된 `<id>/script.json`만 원자적 스트림으로 저장한다. 저장 전후 원본 내용과 연결 폴더를 다시 비교하며 동시 변경은 중단한다. 저장된 메타데이터 이름은 컴파일된 사용자 코드의 표시 정보에 전달하며 원본 실행 코드는 수정하지 않는다.

입력별 잠금·숨김은 공통 런처에서 처리한다. `macroStudioFieldPreferences`는 매크로 ID·필드 이름·타입별 플래그와 사용자가 명시적으로 잠그거나 숨긴 값만 Chrome 로컬 저장소에 보관한다. 일반 입력 변경은 자동 저장하지 않는다. ISOLATED 진입점이 실제 런처 버튼의 신뢰된 클릭만 `scripts:field`로 전달하고, 워커는 해당 origin에서 사용 가능한 ID와 입력 이름·타입·크기를 검증한다. DOM의 표시 이벤트로 저장 요청을 전달하지 않는다. 다른 사이트로는 그 사이트에 일치하는 매크로 설정만 전달하며 전체 초기화·영구 삭제 때 설정도 지운다. 숨긴 입력과 disabled인 잠금 입력도 실제 실행 값과 신뢰된 제출 스냅샷에 포함한다. 실행 중에는 설정 변경을 막고 완료·오류 뒤 원래 잠금을 복구한다.

실행 창이 열린 상태의 목록 갱신은 마지막으로 확인된 준비 상태를 유지하며 새 결과만 반영한다. 입력 설정 변경 알림은 정의를 재연결하지 않고 상태만 갱신한다. 저장 중 도착한 입력 설정은 완료 응답 뒤에도 재렌더가 필요한 상태를 보존해 적용하며, 입력 초안·창 열림·스크롤과 실행 결과를 유지한다. 사이트 OFF나 실제 삭제·보관은 확인된 결과대로 처리한다.

실행 창의 이름 수정은 신뢰된 저장 버튼 클릭·Enter만 ISOLATED 진입점에서 `scripts:rename`으로 보낸다. 워커는 sender origin에 일치하는 로컬 매크로인지 확인한 뒤 기존 `localScripts.rename`으로 저장한다. 이름 입력은 실행 폼 밖에 두며, 응답의 이름은 실행 제목·목록에 반영하고 실행 입력·잠금·숨김은 유지한다.
