# 설치와 사용

## 처음 설치

1. Node.js 22 이상과 Chrome 135 이상을 준비한다.
2. 저장소에서 `npm ci`, `npm run build`를 실행한다.
3. `chrome://extensions`에서 개발자 모드를 켠다.
4. ‘압축해제된 확장 프로그램을 로드’로 저장소의 `dist`를 선택한다.
5. Macro Studio를 도구모음에 고정하고 아이콘을 누른다. 작은 팝업에서 **이 사이트에 적용**을 ON으로 켜면 파란 버튼이 나타난다.
6. 개인 스크립트를 자동 반영하려면 팝업의 **스크립트 연결·관리**에서 저장소 또는 `local/scripts` 폴더를 연결하고, 안내가 나오면 Chrome의 사용자 스크립트 허용을 켠다. 새 도메인만 선택해 허용한다. [연결 방법](script-sync.md)

Chrome은 등록한 폴더를 계속 읽으므로 `dist`를 Downloads 같은 임시 위치로 옮기거나 지우지 않는다. 폴더를 옮겼다면 새 위치를 다시 등록한다.

## 이미 만든 매크로 실행

해당 사이트에 로그인하고 작은 파란 아이콘을 누른다. 목록에서 작업을 고른 뒤 날짜 등의 값을 선택해 실행한다. 아이콘은 드래그할 수 있고 사이트별로 위치를 기억한다. 진행 중 메뉴를 닫아도 작업은 계속된다. 오류가 나면 다음 작업을 누르지 말고 메시지와 실제 페이지를 확인한다.

처음 설치하거나 초기화한 뒤에는 UNIST를 포함한 모든 사이트가 기본 OFF다. 도구모음 팝업에서 **이 사이트에 적용**을 ON으로 켜면 스크립트가 없어도 파란 버튼을 표시한다. 버튼의 **새 자동화 만들기**를 눌렀을 때 오른쪽 작업실이 열린다. 마지막 스크립트를 삭제해도 직접 켠 사이트는 새 작업을 만들 수 있도록 버튼을 유지한다. OFF로 끄면 같은 사이트의 열린 탭에서도 버튼이 숨겨지며, 선택은 재시작 뒤에도 유지된다. 공개 예제나 동기화된 스크립트가 있어도 자동으로 ON이 되지 않는다. 직접 ON을 선택한 사이트만 켜진다.

OFF는 사이트 권한이나 스크립트 파일을 삭제하지 않는다. 기록 중이면 내용을 보존하고 기록을 끝내며, 이미 실행 중인 매크로는 완료한 뒤 버튼이 숨겨진다. ON으로 돌아올 때 기존 권한이 있으면 다시 요청하지 않는다.

## 스크립트 보관·복원·삭제

1. 페이지의 Macro Studio 아이콘을 열고, 스크립트 오른쪽의 **보관함으로 이동** 아이콘을 누른다. 확인 팝업에서 확인하면 실행 목록에서 빠진다. 취소하면 유지된다.
2. 아이콘 메뉴 아래의 **스크립트 보관함**을 연다. 별도 탭에서 빌드에 포함된 모든 스크립트를 확인할 수 있다. 이 화면에서 사용 중인 스크립트를 보관할 때도 확인 팝업이 열린다.
3. **보관 중 → 복원**을 누르면 해당 사이트의 실행 목록에 다시 나타난다.
4. 더 이상 필요하지 않으면 **보관 중 → 삭제 → 확인 창의 삭제**를 누른다. 이 확장 화면에서는 되돌릴 수 없다.

상태는 확장의 로컬 저장소에 남아 페이지·확장 새로고침, 브라우저 재시작, 같은 id로 재빌드한 뒤에도 유지된다. 다른 탭의 실행 목록도 갱신된다. 확장을 제거하면 해당 상태도 제거된다. 이미 실행 중인 작업을 중단하는 기능은 아니다.

삭제는 확장의 실행 목록과 보관함에서 항목을 제거하는 기능이다. 저장소의 `local/scripts/` 원본과 개인 설정 파일을 지우거나 수정하지 않는다. 개인 스크립트의 파일까지 제거하려면 실행 중인 작업이 없는지 확인한 뒤 해당 원본 폴더를 직접 정리한다. 연결된 폴더는 다음 동기화에 반영되며, 빌드에 남은 사본은 다음 빌드에 정리된다. 공통 UNIST 예제는 공개 소스로 계속 포함된다.

## 새로운 작업 기록

1. 대상 사이트를 연 뒤 도구모음의 Macro Studio 팝업에서 **이 사이트에 적용**을 ON으로 켠다. 처음에는 해당 사이트만 접근 권한을 요청한다.
2. 페이지의 **파란 버튼 → 새 자동화 만들기**로 작업실을 연다. 다른 출처의 내부 화면도 필요하면 **내부 화면 자동 감지 켜기**를 누른다. 이 선택 권한은 한 번 허용하면 계속 유지된다.
3. 감지한 내부 사이트 중 기록할 화면만 선택하고 **선택한 내부 화면 허용**을 누른다. 광고 등은 선택하지 않아도 된다. 이미 허용한 주소는 ‘이미 허용됨’으로 표시하고 다시 요청하지 않는다. UNIST의 포탈·SAP는 기본 프로필에 포함된다.
4. 이름을 적고 ‘새 기록 시작’을 누른다. 이전 기록은 새 기록으로 대체되므로 보관할 기록은 JSON으로 먼저 저장한다.
5. 같은 탭에서 평소 작업을 수행한다. 입력·클릭·페이지 진입이 기록되며, 화면 영상은 저장되지 않는다.
6. ‘기록 끝내기’를 누르고 단계를 검토한다. 기록은 최대 600단계다.
7. 불필요하거나 전달하지 않을 단계는 삭제한다. 단계마다 모드나 변수 이름을 정할 필요는 없다.
8. 목적과 ‘바뀌는 값’을 적고, 항상 표시되는 전달 내용을 검토한 뒤 프롬프트를 복사한다. 저장소를 연 Codex·Claude Code에 붙여 넣는다. 에이전트는 설명한 값을 실행 입력으로 만들고 나머지 기록값을 기본값으로 사용한다. 사용자가 지정한 수동 단계와 실제 최종 제출은 자동 실행하지 않는다. 버튼 이름에 따른 자동 분류는 참고 자료이며, 중간 준비 화면인지는 사이트 문서·기존 구현·실제 화면으로 확인한다.

기록은 자동으로 완성된 매크로가 아니다. 실제 화면에서 선택자와 대기 조건을 확인하고, 에이전트가 실행 코드를 작성한 뒤 등록한다. [제작 안내](create-script.md)

작업실이 열려 있는 동안 대상 탭의 내부 화면을 주기적으로 다시 확인한다. 기록 중 새 내부 사이트가 나타나면 목록에 안내하며, 사용자가 선택해 허용하면 진행 중인 기록에 연결한다. 다른 탭으로 이동해도 추가 화면 확인·허용의 대상은 기록 중인 탭으로 유지된다. 자동 감지 자체가 사이트 권한을 자동으로 부여하지는 않는다.

자동 감지를 거부해도 이미 허용된 현재 페이지에서는 기록을 시작할 수 있다. 한 번 허용한 사이트는 권한을 취소하거나 확장을 제거하기 전까지 계속 사용할 수 있다. 내부 프레임 연결이 일시적으로 실패하면 ‘기록기 다시 연결’로 재시도한다.

## 업데이트

개인 스크립트만 바꿨다면 연결된 폴더에서 자동 반영된다. 공통 확장 기능·manifest를 바꿨다면 `npm run build` → 확장 카드 새로고침 → 작업 웹페이지 새로고침 순서로 적용한다. 버전 번호는 작은 수정마다 변경하지 않아도 된다.

기존 UNIST 도우미와 이 확장을 동시에 켜두지 않는다. 기존 확장을 끈 뒤 새 확장을 테스트한다. 이 저장소는 기존 확장 폴더를 자동 수정하거나 삭제하지 않는다.
