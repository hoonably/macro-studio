# 문제 해결

## 아이콘이 보이지 않음

도구모음의 Macro Studio 팝업에서 **이 사이트에 적용**이 ON인지 확인한다. ON이면 스크립트가 없어도 파란 버튼이 나타난다. 빌드한 `dist`를 로드했는지 확인한다. 개인 스크립트는 작업실의 **스크립트 연결**에서 동기화 상태·오류·사이트 권한을 확인한다. 공통 확장 코드를 수정했다면 `npm run build` 후 확장 카드와 웹페이지를 모두 새로고침한다. 자동화할 사이트는 개인 스크립트의 matches 범위에 포함하고 필요한 사이트 권한을 허용한다. Chrome 설정·웹스토어 같은 보호된 페이지에는 주입할 수 없다.

## 스크립트를 저장해도 반영되지 않음

**스크립트 연결**에서 사용자 스크립트 허용, 폴더 읽기, 새 사이트 권한을 확인하고 **지금 동기화**를 누른다. Chrome에서 사용자 스크립트 허용을 켠 직후에도 계속 허용을 요구하면 **허용 설정 반영하고 계속**을 누른다. 이 작업은 초기 설정 반영을 위한 것이며, 이후 개인 스크립트 저장마다 필요하지 않다. 파일 오류가 있으면 마지막 정상 버전을 유지하고 오류를 표시한다. 실행 중 변경은 완료 후 반영한다. [상세 안내](script-sync.md)

## 아이콘이 두 개 보임

웹 스토어판과 개발용 Macro Studio 또는 다른 자동화 확장이 함께 켜져 있는지 확인한다. 새 확장을 테스트할 때 기존 확장을 끈다. 포탈 내부 프레임의 UI 중복은 코드에서 방지한다.

## 설치 후 스크립트 목록이 비어 있음

새 설치의 실행 목록은 비어 있는 것이 정상이다. [개인 스크립트 제작 안내](create-script.md)에 따라 작업을 기록하고 에이전트가 연결 폴더에 파일을 만들도록 한다. 특정 사이트의 업무 매크로나 별도 설정 파일은 자동 설치되지 않는다.

## 입력 일부가 기록되지 않음

비밀번호·인증번호 필드는 기록하지 않는다. 사용자 정의 입력, 일부 SAP 위젯, shadow DOM, 다른 출처 프레임은 추가 확인이 필요하다. 사이드패널의 **내부 화면 자동 감지**에서 기록할 사이트를 선택해 허용한다. 새로 허용한 화면은 기록을 재시작하지 않고 연결한다. 일시적으로 사라진 프레임은 화면이 열린 뒤 **기록기 다시 연결**로 재시도한다. 특수 프레임이나 자동 감지로 확인하지 못한 구조는 `tools/inspect.js`로 조사한다. 기록은 최대 600단계다.

## 사이트 접근을 먼저 허용하라는 메시지

도구모음에서 Macro Studio를 연 다음 **이 사이트에 적용**을 ON으로 켠다. 다른 탭으로 전환했다면 대상 탭에서 확장을 다시 열어 현재 URL을 확인한다. 권한 요청이 거부됐다면 Chrome의 확장 사이트 접근 설정을 확인한다.

## 다른 사이트에서 Invalid URL 오류가 뜸

작업실을 열어둔 채 새 사이트로 이동하면 Chrome이 사이트 권한을 받기 전까지 탭 주소를 제공하지 않을 수 있다. 확장은 이미 허용된 내부 화면 감지 기능으로 최상위 페이지 주소를 확인하고, 해당 사이트 접근은 **이 사이트에서 사용하기**를 눌렀을 때 요청한다. 내부 화면 감지가 꺼져 있고 주소도 보이지 않으면 대상 사이트에서 도구모음의 Macro Studio를 다시 연다.

일반 HTTPS 사이트와 `http://localhost:3000` 같은 개발 서버에서도 기록할 수 있다. 이전 버전의 `Invalid URL`은 빈 주소를 그대로 변환하던 오류다. 새 버전에서는 주소를 확인할 수 없는 이유를 안내하고, 다른 탭의 오래된 권한 상태로 기록을 시작하지 않는다.

## 오류 버튼이 계속 남아 있음

Chrome의 확장 오류 목록에는 이전 실행 기록도 남는다. 코드 수정과 확장·페이지 새로고침 후 발생 시간이 새 오류인지 확인한다. 목록을 지워도 확장을 삭제하는 것은 아니지만, 우선 실제 에러 메시지를 확인한다.

## 포탈이 흰 화면이 됨

자동화를 다시 누르지 말고 페이지 상태를 확인한다. 브라우저 직접 제어 없이 수동으로 복구하고 막힌 메뉴·오류 메시지를 에이전트에게 전달한다. 흰 화면을 봇 차단으로 단정하지 않는다.

## postMessage의 target origin이 내부 화면 주소와 다르다는 오류

화면이 전환되는 동안 프레임에는 임시 문서가 남아 있을 수 있다. 실제 업무 앱의 출처가 준비되기 전에 메시지를 보내지 않도록 개인 매크로의 프레임 상태 검증을 확인한다. 응답의 origin·source·실행 id·문서 instance도 검증한다. [공통 SAP 어댑터 안내](sap-adapter.md)를 참고한다.

## 작업이 중간에 멈춤

이미 입력하거나 열린 신청서가 남아 있을 수 있다. 화면과 오류를 먼저 확인한다. 자동화는 오류를 숨기고 계속 진행하지 않으며, 최종 제출을 자동 재시도하지 않는다. 입력값을 바꾸려면 현재 열린 준비 화면과 이미 반영된 값을 먼저 확인한다.
