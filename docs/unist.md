# UNIST 국내출장 예제

`scripts/examples/unist-travel/`과 `profiles/unist.json`은 개인 스크립트를 만들 때 참고하는 소스다. 기본 빌드에는 포함되지 않으며, 설치·초기화 후 출장 스크립트가 자동으로 나타나지 않는다.

## 참고 흐름

예제 소스는 로그인된 UNIST 포탈에서 다음 흐름을 구현한다.

```text
일반행정 → 인사 → 국내출장 신청 → 신청
→ 날짜·고정값 입력 및 계산값 검증
→ 신규 결재상신 → 예 → 저장 결재선 선택 및 순서 검증
→ 멈춤: 최종 결재상신은 사용자가 직접
```

국내출장 앱은 `ZHRW3218`, 전체출장 조회 앱은 `ZHRW3213`이다. 포탈 메뉴에서는 국내출장 신청을 선택한다. 소스에는 SAP 독립 탭용 진입점도 있다.

## 개인 스크립트로 재사용

에이전트에게 실제 기록과 이 문서를 전달해 `local/scripts/<id>/`에 개인 스크립트를 만들도록 요청한다. `profiles/unist.json`의 사이트 범위·로드 순서를 참고하고, 필요한 소스를 개인 폴더에 가져와 `script.json`에서 명시한다. 예제의 UI 등록 부분은 개인 스크립트의 id로 맞추며 중복 등록하지 않는다. 포탈과 SAP 기능이 미리 로드되어 있다고 가정하지 않는다.

`config.example.json`은 설정 구조의 참고 자료다. 기관·목적·비고·예상 계산값·정확한 저장 결재선 이름·신청자 다음 결재자 순서는 개인 스크립트가 명시적으로 읽는 설정으로 준비한다. 과거의 `local/profiles/unist-travel.json`을 복사하거나 수정하는 것만으로는 빌드에 반영되지 않는다. 저장 결재선은 포탈에 미리 존재해야 한다.

현재 예제의 재원은 **기타 + 자비**로 고정되어 있다. 외부지원·타기관공동연구·중복출장·공용차량·학회출장은 해제한다. 다른 재원을 사용하려면 `fill.js`의 해당 항목과 검증을 실제 화면에 맞게 수정한다. 이 예제의 조합을 모든 사용자에게 맞는 기본값으로 가정하지 않는다.

필수 설정이 없으면 실행 전에 멈추도록 유지한다. 완성한 개인 스크립트는 연결된 `local/scripts/`에서 동기화하며, 공통 확장 코드를 바꾼 경우에만 빌드·확장 새로고침이 필요하다.

필요한 예제 코드를 개인 스크립트에 포함한 경우 `features.travelRequest.runFromPortal(date, report, inputs)` 또는 SAP 독립 탭의 `runFromList(date, report, inputs)`로 기존 경로를 재사용할 수 있다. `date`는 `YYYY.MM.DD`, `inputs`는 선택 항목인 `startTime`, `endTime`(`HH:MM`) 및 `preset`(개인 고정값)이다. 같은 날의 종료 시간이 시작 시간보다 늦어야 하며, 잘못된 날짜·시간은 화면 이동 전에 거부한다. 실행별 설정은 공통 기본값을 변경하지 않는다.

기존과 출장시간 길이가 같으면 설정한 여비 예상액을 검증한다. 시간 길이가 달라지면 여비 규정을 추정하지 않고 SAP 계산값이 유효한 숫자인지 확인한다. 최종 상신 전에 사용자가 계산된 여비를 확인한다. 결재선 창이 열린 상태에서 재실행하면 날짜·시간·고정값이 모두 일치하는지 확인하고, 입력값을 바꾸려면 먼저 창을 닫아야 한다.

## 구현상의 이유

- SAP 동적 ID 대신 `data-cust-sid…` 속성의 안정적인 업무 필드명을 찾는다.
- 기본 입력 API로 하나씩 변경하고 ready 상태와 실제 값 반영을 확인한다.
- 이미 선택된 메뉴와 값이 같은 항목은 건너뛴다.
- 결재선은 표시 이름으로 하나만 찾고 신청자 이후 결재자들의 순서를 확인한다.
- 출처가 다른 포탈/SAP 프레임은 origin·source·실행 id·문서 instance를 확인한다.
- 메뉴나 버튼이 중복되거나 알 수 없는 팝업이 나타나면 멈춘다.

기존 개인 확장에서 사용자가 정상 동작을 확인했던 흐름을 일반화한 것이다. 이 저장소로 옮긴 뒤의 검사는 오프라인이며, 실제 포탈에서의 재확인은 별도로 필요하다. 이전 브라우저 제어 중 나타났던 흰 화면의 원인은 확정되지 않았다.

로그인·추가 인증은 사용자가 수행한다. 이 작업 경로에서 CAPTCHA가 관찰되지 않았다는 사실을 UNIST 전체의 인증 정책으로 일반화하지 않는다.
