# 개인 스크립트 자동 동기화

## 처음 연결

1. 작업실의 **사용 준비**에서 개인 매크로를 저장할 폴더를 선택한다. 원하는 위치에 빈 폴더를 만들어 선택해도 된다. 이미 매크로가 있어야 연결되는 방식이 아니다.
2. **선택한 사용 폴더의 전체 경로**를 붙여넣고 **이 경로로 저장 위치 확인**을 누른다. Mac은 Finder에서 그 폴더를 선택하고 ⌥⌘C, Windows는 탐색기 주소 표시줄에서 경로를 복사한다. Chrome은 전체 OS 경로를 제공하지 않으므로 처음 한 번 사용자 확인이 필요하다. 확인 후에는 입력칸과 긴 설명을 숨기고 저장 위치 한 줄만 표시한다. 필요할 때만 **경로 수정**으로 다시 연다. 폴더를 바꾸면 이전 경로 확인은 해제된다.
3. Chrome 실행 허용이 꺼져 있으면 **Chrome 실행 허용 설정 열기** → 확장 세부정보의 **사용자 스크립트 허용** 켜기 → 작업실의 **허용 상태 다시 확인** 순서로 진행한다. Chrome 135–137은 개발자 모드를 사용한다. 이 확인 버튼은 확장을 재로드하지 않는다.
4. 자동화할 웹사이트 탭을 열고 **이 사이트에서 사용하기**를 눌러 허용한다. **내부 화면 자동 감지 켜기**로 내부 주소를 확인하고, 필요한 주소를 선택해 **선택한 내부 화면 허용**을 누른다. 관계없는 주소는 **선택하지 않은 내부 사이트는 제외하고 계속**으로 명시적으로 제외할 수 있다. 자동으로 모든 사이트를 허용하지 않는다.
5. 준비 항목이 완료되면 **준비 완료 후 매크로 만들기**를 누른다. 그 전에는 기록·생성 화면과 프롬프트 복사를 진행할 수 없다. 연결·경로·권한이 해제되면 생성이 다시 잠기고 기존 기록과 설명은 유지된다. 진행 중인 기록은 끝낼 수 있다.

연결한 폴더 바로 아래 `<id>/script.json`과 `script.js`를 둔다. 기존 저장소를 선택하면 `local/scripts`, 별도 상위 폴더의 `scripts` 구조도 정해진 위치만 찾아 사용한다. 관련 없는 폴더를 재귀 탐색하지 않는다. 복사하는 지시문에는 실제 인식한 폴더의 절대경로가 포함되므로 에이전트는 그 아래에 `<id>/`를 만든다. `scripts`를 중복으로 만들거나 다른 작업 폴더에 저장하지 않도록 명시한다.

이후 지시문에 적힌 `<사용 폴더>/<id>/script.json`과 실행 파일을 저장하면 작업 목록과 열린 사이트의 버튼에 반영된다. 공통 확장 코드나 manifest를 바꾸면 빌드 완료를 감지해 확장을 자동으로 업데이트한다. 특정 사이트의 업무 매크로를 기본 제공하지 않으며, 개인 스크립트는 같은 폴더 연결 방식으로 사용한다.

공통 기능 업데이트는 `git pull` → `npm run build`로 받는다. 완료된 빌드의 내용이 달라졌을 때만 자동 적용하며, 같은 내용의 재빌드와 실패·진행 중인 빌드는 재적용하지 않는다. 작업실·팝업·연결 화면이 보이면 약 2초 간격으로, 닫혀 있어도 Chrome 알람으로 약 30초 간격으로 확인한다. Chrome이 절전 중이면 늦어질 수 있다.

기록 중이거나 스크립트가 실행 중이면 완료할 때까지 미룬다. 이미 끝낸 기록은 업데이트를 막지 않는다. 기록·자동화 이름·목적·바뀌는 값은 업데이트 직전에 확장 전용 IndexedDB에 잠시 보관하고 새 코드에서 세션 저장소로 복원한 뒤 임시 사본을 지운다. 연결한 폴더와 스크립트도 유지한다. 작업실이 닫히면 사이트의 파란 버튼으로 다시 연다. 웹사이트 자체를 자동 새로고침하지 않는다.

이 자동 감지 기능이 없는 이전 버전에서는 처음 한 번만 확장을 새로고침해야 한다. 기존 기록은 먼저 JSON이나 프롬프트로 보관한다. **연결 상태·관리 → 확장 기능 업데이트 적용**으로 수동 적용할 수도 있다. Chrome이 폴더 읽기 권한을 다시 요청하면 **폴더 읽기 다시 허용**을 누른다.

## 확인 주기와 유지되는 것

- 작업실이나 동기화 화면이 보이면 약 2초 간격으로 확인한다.
- 화면이 닫혀 있어도 Chrome 알람으로 약 30초 간격으로 확인한다. 절전·Chrome 종료 동안에는 확인이 늦어진다.
- 등록한 스크립트와 폴더 핸들은 확장의 IndexedDB에 보관한다. 서비스 워커 재시작과 확장 업데이트 뒤에도 마지막 정상 코드를 다시 등록한다.
- Chrome이 폴더 권한을 다시 요구하면 **폴더 읽기 다시 허용**을 누른다. 폴더 접근을 잃어도 이미 가져온 스크립트는 유지한다.
- **동기화 중지**는 폴더 감지만 중지한다. 마지막으로 가져온 스크립트는 유지하며 보관·삭제는 스크립트 보관함에서 한다.
- 연결한 폴더에서 스크립트 디렉터리를 제거하거나 `enabled: false`로 바꾸면 가져온 실행 목록에서 제외한다. 단순히 파일 저장이 잠깐 불완전해진 경우에는 마지막 정상 버전을 유지한다.
- 보관·삭제 상태는 id로 유지한다. 저장하거나 폴더를 다시 연결해도 삭제한 id를 되살리지 않는다.

파일 변경은 코드와 목록만 갱신한다. 사이트의 업무 작업은 파란 버튼에서 직접 실행한다. 실행 중인 작업에는 새 코드를 덮어쓰지 않으며 완료 후 다음 동기화 때 적용한다.

## 스크립트 작성

기존 `script.json` 형식을 사용한다. `files`에 명시된 폴더 내부 `.js`만 읽는다. 모듈 import 대신 순서대로 로드할 파일을 나열하고, UI 등록은 동기적으로 수행한다. 실제 작업은 `run`에서만 시작한다.

`world: "ISOLATED"`는 개인 코드를 Chrome의 `USER_SCRIPT` world에서 실행한다. 페이지와 확장 content script의 JavaScript 전역에서 분리된다. SAP 기본 API나 기존 MAIN 사이트 기능을 사용하면 `world: "MAIN"`을 지정한다. 각 world의 코드가 수집한 UI 정의는 공통 실행기에 표시하며 입력값·진행 상황·완료 결과를 연결한다. 확장 권한은 사용자 코드에 노출하지 않는다.

잘못된 JSON·JavaScript, 누락된 파일, 등록 실패는 동기화 화면에 표시한다. 새 매크로에 실행 파일이나 `script.json`이 빠졌으면 어떤 파일이 없는지 안내한다. 빈 준비 폴더는 오류로 처리하지 않는다. 마지막 정상 버전이 있으면 유지한다. 실제 페이지에서 초기화가 실패한 스크립트는 오류를 표시하고 다른 스크립트를 계속 사용할 수 있다. 선택자와 사이트 동작은 [제작 안내](create-script.md)에 따라 검증한다.

공식 API: [Chrome userScripts](https://developer.chrome.com/docs/extensions/reference/api/userScripts), [파일·폴더 접근](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access), [Chrome 알람](https://developer.chrome.com/docs/extensions/reference/api/alarms).
