# 데이터와 권한

## 저장하는 것

| 데이터 | 위치 | 수명 |
|---|---|---|
| 아이콘 위치 | 각 사이트의 localStorage, 자체 키 | 사용자가 사이트 저장소를 지울 때까지 |
| 사이트별 ON/OFF | 확장의 `chrome.storage.local`, origin과 boolean만 저장 | 재시작·재빌드 후 유지; 확장 제거 시 삭제 |
| 보관·삭제한 스크립트 id | 확장의 `chrome.storage.local` | 페이지·확장 새로고침, 브라우저 재시작, 재빌드 후 유지; 확장 제거 시 삭제 |
| 클릭·입력 기록 | 확장의 `chrome.storage.session` | 현재 브라우저 세션; 새 기록 시작·기록 지우기·확장 새로고침 등으로 제거될 수 있음 |
| 개인 설정·스크립트 | 저장소의 `local/` | 사용자가 관리 |
| 연결한 폴더 핸들·가져온 개인 스크립트 코드 | 확장의 IndexedDB | 동기화 중지 뒤에도 마지막 정상 코드 유지; 확장 제거 시 삭제 |
| 개인용 빌드 | `dist/` | 다음 빌드까지; 개인값 포함 가능 |
| JSON 내보내기 | 사용자가 저장한 파일 | 사용자가 관리 |

기록은 현재 하나만 보관한다. 새 기록을 시작하면 기존 기록을 대체한다. 중요한 기록은 JSON으로 저장한다.

## 제외하는 것

비밀번호·인증번호·카드 입력과 일반적으로 비밀값을 뜻하는 필드, hidden/file 입력을 건너뛴다. URL query와 fragment는 저장하지 않으며 흔한 토큰 패턴도 지운다. 쿠키·로그인 자격 증명·네트워크 응답·키보드 전체 로그·화면 영상은 읽거나 수집하지 않는다.

이 규칙이 모든 사이트의 개인 정보를 알아내는 것은 아니다. 이름·기관·업무 내용 같은 일반 입력과 URL 경로·페이지 제목·라벨에는 개인 정보가 남을 수 있다. 단계 목록과 항상 표시되는 프롬프트 미리보기를 확인하고, 전달하지 않을 단계는 삭제한다. ‘바뀌는 값’ 설명을 적어도 기록한 입력값은 지워지지 않는다.

기록기의 허용 이벤트에 포함되지 않는 사용자 정의 위젯, closed shadow DOM, 허용하지 않은 출처 프레임 등은 기록되지 않거나 불완전할 수 있다. 중요한 작업은 실제 화면과 읽기 전용 진단으로 보완한다.

## 권한

- `activeTab`: 사용자가 확장을 연 탭에 일시적으로 접근
- `scripting`: 허용된 페이지에 기록기와 아이콘 주입
- `storage`: 기록을 확장 전용 세션 저장소에 보관
- `sidePanel`: 브라우저 옆에 작업실 표시
- `userScripts`: 사용자가 연결한 폴더의 개인 코드를 USER_SCRIPT 또는 MAIN world에서 실행. Chrome의 사용자 스크립트 허용 설정을 사용한다.
- `alarms`: 작업실이 닫혀 있어도 약 30초마다 연결한 폴더의 변경 확인
- 폴더 읽기: 사용자가 선택한 스크립트 디렉터리의 메타데이터와 명시한 실행 파일만 읽음. 파일 쓰기·삭제 권한은 요청하지 않음
- 선택 권한 `webNavigation`: 현재 대상 탭의 실제 프레임 주소 확인. 자동 감지를 켤 때 한 번 요청하며, 사용자가 거부해도 허용된 현재 페이지의 기록은 가능하다.
- 기본 사이트 범위: 새 설치에는 없음. 개인 빌드에는 포함된 개인 스크립트가 선언한 사이트만 추가됨
- 선택 사이트 범위: 사용자가 팝업의 **이 사이트에 적용 ON** 등으로 허용한 개별 http(s) 사이트

팝업의 OFF는 페이지 버튼과 새 실행을 끄는 설정이다. 기존 사이트 권한과 등록 코드는 유지하며, 권한 자체의 회수는 Chrome의 확장 설정에서 한다. 다른 출처의 내부 화면 권한은 기록 작업실에서 별도로 선택한다.

기록은 시작한 탭에서만 수집한다. 허용한 다른 출처 iframe을 같은 탭에서 방문하면 그 이벤트도 포함할 수 있다. 다른 탭은 기록하지 않는다.

자동 감지는 작업실이 보이는 동안 선택한 탭 또는 기록 중인 탭만 조회한다. 프레임 주소에서 origin만 추려 목록에 표시하며, 프레임의 전체 URL·query·세션 경로를 감지 목록이나 저장소에 남기지 않는다. 허용되지 않은 내부 사이트는 체크하지 않은 후보로 표시한다. 사용자가 후보를 선택하고 버튼을 눌러야 Chrome에 해당 사이트 권한을 요청한다. 감지된 모든 프레임을 자동으로 허용하지 않는다.

## 전송과 공유

확장은 원격 코드·추적·외부 AI 요청을 사용하지 않는다. 사용자가 프롬프트를 복사하거나 JSON을 내려받은 뒤 전달할 상대를 선택한다. 매크로 입력에 따른 대상 사이트 자체 통신은 평소 작업처럼 발생한다.

GitHub에 올릴 때는 `local/`, `dist/`, 캡처·HTML·HAR 등을 제외한다. 공유용 확장은 `npm run build:public`로 별도로 만든다. 공개 저장소의 예제는 개인 실제 설정과 분리되어 있다.

## 처음 상태로 초기화

‘스크립트 연결’ 화면 아래의 **처음 상태로 초기화**에서 삭제 범위를 확인하고 **기록과 개인 설정 삭제**를 누른다. 화면을 열기만 하면 아무것도 지우지 않는다. 현재 기록, 사이트별 ON/OFF, 스크립트 목록·보관함, 폴더 핸들·가져온 코드, 동기화 상태와 추가 사이트·프레임 감지 권한을 지운다. 빌드에 남은 스크립트의 id는 삭제 상태로 기록해 초기화 뒤 되살아나지 않게 한다. 실행 중인 개인 매크로가 있으면 완료할 때까지 초기화를 막는다.

저장소의 `local/`과 내려받은 파일은 별도로 관리해야 한다. 개인 코드가 포함된 `dist/`는 개인 원본을 정리한 뒤 다시 빌드한다. 웹사이트 로그인·데이터와 사이트에 저장된 아이콘 위치는 건드리지 않는다. 이미 열려 있는 웹페이지와 작업실은 새로고침해야 로드된 코드·입력 화면도 비워진다.

Chrome의 사용자 스크립트 허용 설정은 확장이 끌 수 없다. 선택 권한을 회수해도 Chrome은 [이전 승인을 기억해 재요청을 생략할 수 있다](https://developer.chrome.com/docs/extensions/reference/api/permissions#step-5-remove-the-permissions). 설치·권한 안내까지 처음부터 시험하려면 확장을 제거하고 다시 등록한다. 필수 manifest 권한은 초기화로 회수하지 않는다.
